# 每条私信独立回复与独立模型对话

## 目标

- 对方每发一条私信，都要有一条回复，不再“整个会话只回一次”。
- 对方连续发两条时，先逐条生成、逐条入 outbox，再按 B站请求节奏发送。
- 新消息到达时，不因为上一轮回复冷却而丢弃；冷却只影响发送节奏，不影响排队。
- 模型对话独立于“控制插件的 DSH 会话”，拥有自己的记忆、人设和上下文。

## 结构

```text
B站新私信
  → inbox（按 msg_id 幂等认领）
  → policy（主人 / 互关 / 陌生人）
  → model-chat（独立持久化会话；可选）
  → fallback（人格模板 / 听到啦）
  → outbox（每条消息一条）
  → sender worker（真实 sendDm）
```

## 独立模型会话

- 文件：`<账号数据目录>/model-chat.json`
- 每个 talker 保留最近 24 条消息（12 轮）。
- 人设来自 `settings.personaFile` / `personaDir`，与插件设置共用，但对话上下文不写入 DSH 会话。
- API key 只从 DSH credentials 读取 `DEEPSEEK_API_KEY`，不写入设置、日志或仓库。
- 调用超时 20 秒；失败自动回退到模板/固定确认，不阻塞队列。

## 发送节奏

- outbox 的 `next_at` 在入队时立即生效，不再额外等待 20 分钟。
- 一个 tick 最多发送 5 条；第 1 条后等待 900ms，避免瞬时并发。
- 每日私信额度仍生效；额度用尽时保留 pending，第二天继续，不伪造 sent。
- 发送结果未知进入 `unknown`，不自动重试，避免重复私信。

## 测试

- `node scripts/verify-02-model.mjs`：独立会话持久化、system prompt、Authorization、缺 key 回退。
- `node scripts/gate-check.mjs`：全量门禁。
